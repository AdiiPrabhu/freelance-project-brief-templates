# Mobile app development brief

## 1. Product outcome
- What user or business problem must the app solve?
- Who is the primary user?
- What observable result defines a successful first release?
- Which assumptions still need validation?

## 2. Release boundary
- Platforms: iOS, Android, responsive web, tablet
- Supported operating-system versions and devices
- Included user roles
- Included end-to-end user journeys
- Explicitly deferred journeys and features

## 3. Functional requirements
For each capability, describe the trigger, happy path, permissions, data created, failure states and acceptance test.

- Authentication and account recovery
- Profiles and permissions
- Payments or subscriptions
- Search, filters and saved states
- Notifications
- Offline or poor-network behaviour
- Admin and support tools

## 4. Data and integrations
- Existing backend or API responsibility
- Third-party services and account owners
- Data migration and import requirements
- Analytics and crash reporting
- Privacy, retention and deletion expectations
- Security or compliance review required

## 5. Design and content
- Existing research, flows or design system
- Required screens and states
- Accessibility target
- Copy, imagery and localisation owner
- App-store assets and listing responsibility

## 6. Delivery and acceptance
- Target release date and why it matters
- Review environments and test accounts
- Named approver and feedback turnaround
- Device and browser test matrix
- Definition of release-ready
- Store submission and rejection responsibility

## 7. Commercial boundaries
- Budget or working range
- Payment milestones
- Included revision rounds
- Change-request approval process
- Warranty period and maintenance exclusions
- Source-code ownership and third-party licences

## 8. Open decisions before a fixed quote
- [ ] Primary journeys approved
- [ ] Roles and permissions approved
- [ ] Integration access verified
- [ ] Data migration quantified
- [ ] Acceptance tests agreed
